# my-tasks 要件定義 v1.0

2026-10-14 確定。変更する場合はこのファイルを更新し、末尾の変更履歴に記録する。

## 1. 概要

- **目的**：仕事・学習・私用のタスクを一元管理し、「今日やるべきこと」が一目でわかる状態にする
- **利用者**：自分ひとり（認証なし）
- **利用環境**：PCブラウザのみ。自分のPCでローカル起動して使う
- **開発方針**：実用優先。実装はClaudeが主導し、本人はレビュー・受け入れ確認を行う

## 2. 機能要件

### F1. タスク管理（CRUD）

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| タイトル | 文字列（〜200文字） | ○ | |
| メモ | テキスト | | |
| 期限日 | 日付 | | |
| 期限時刻 | 時刻 | | 期限日がある場合のみ設定可 |
| 優先度 | 高 / 中 / 低 | ○ | 初期値：中 |
| ステータス | 未着手 / 進行中 / 完了 | ○ | 初期値：未着手。完了日時を記録 |
| 親タスク | タスクID | | サブタスクの場合のみ |
| 繰り返しルール | ルールID | | 繰り返しから生成された場合のみ |

**期限の扱い**

- 期限は「日付のみ」「日付＋時刻」「なし」の3通り
- 期限切れ判定：時刻ありはその時刻を過ぎたら、日付のみはその日が終わったら期限切れ
- 完了済みタスクは期限切れ扱いしない

### F2. 一覧・並び順

**ビュー**

| ビュー | 表示対象（未完了のみ。完了済みビューを除く） |
|---|---|
| 今日 | 期限が今日、または期限切れ |
| 今後 | 期限が明日以降 |
| 期限なし | 期限が未設定 |
| 完了済み | ステータスが完了（完了日時の新しい順） |

**既定の並び順**

1. 期限の近い順（同日内は時刻ありを時刻順に先頭、日付のみはその日の末尾＝23:59扱い）
2. 優先度の高い順
3. 作成日時の古い順

**表示**

- 期限切れは色を変えて強調する

### F3. サブタスク（1階層）

- サブタスクは親と同じ項目を持つ完全なタスク（期限・優先度・ステータスあり）
- 階層は1段のみ。サブタスクの下にサブタスクは作れない（API・DBの両方で禁止）
- 一覧では親の下にインデント表示し、親に「2/5 完了」の進捗を表示する
- サブタスクがビュー条件を満たす場合は、親ごと表示する（例：サブタスクだけ期限が今日 → 今日ビューに親＋該当サブタスク）
- 未完了サブタスクが残る親を完了にしようとした場合は、確認ダイアログを出し、OKならサブタスクも一括で完了にする
- 親を削除するとサブタスクも削除する（確認ダイアログあり）

### F4. 繰り返しタスク（日付到来で生成）

**ルール**

- パターン：
  - 毎日
  - 毎週（曜日を複数選択可）
  - 毎月（日付指定。存在しない日付、例：31日は、その月の最終日）
- ルールはひな形を持つ：
  - タイトル、メモ、優先度、期限時刻（任意）
  - サブタスク構成（タイトル・優先度）
- ルールには開始日を持つ。終了日は任意

**生成**

- 発生日の0時に、期限日＝発生日のタスクを1件生成する。サブタスクもひな形からコピーする
- 前回分が未完了でも生成は止めない（独立したタスクとして積み上がる）
- アプリ停止中に逃した回：起動時に、逃した回のうち**直近の1件のみ**を生成する
- 二重生成防止：「ルールID＋発生日」に一意制約をかける

**ルールの変更・停止**

- ルールの停止・削除時は、以降の生成を止めるだけにする。生成済みタスクは残す
- ルール編集時の変更は、次回生成分から反映する（生成済みタスクには影響しない）

### F5. バックアップ

- 全データ（タスク・繰り返しルール）をJSONでエクスポートできる
- エクスポートしたJSONをインポートできる（既存データは全置換。実行前に確認ダイアログを出す）

## 3. 非機能要件

| 区分 | 要件 |
|---|---|
| 永続化 | 再起動後もデータが残る。H2ファイルモード（`data/` 配下に保存） |
| 性能 | タスク数千件で一覧表示1秒以内 |
| 起動 | コマンド（またはバッチ）1つでフロント・バックを起動できる |
| タイムゾーン | Asia/Tokyo 固定 |
| 対応ブラウザ | 最新版 Chrome / Edge |

## 4. 技術構成

- **フロントエンド**：
  - React + TypeScript（Vite）
  - TanStack Query
  - React Hook Form + Zod
- **バックエンド**：
  - Spring Boot 4 / Java 21
  - Spring Data JPA
  - H2（ファイルモード）
  - `@Scheduled` による繰り返し生成。起動時にも追いつき生成を行う
- **API設計方針**：
  - REST
  - Entityを直接 `@RequestBody` で受けない。リクエスト用・レスポンス用のDTOを分ける

## 5. スコープ外

- 認証・複数ユーザー
- スマホ対応
- 外部公開・デプロイ
- 通知（メール・プッシュ・デスクトップ通知）
- 添付ファイル
- カレンダー表示
- タグ・プロジェクト分類（将来の拡張候補）
