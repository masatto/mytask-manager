# mytask-manager 画面設計 v1.6

[requirements.md](requirements.md) v1.0 に基づく。

## 1. 画面一覧

| ID | 画面 | URL | 概要 |
|---|---|---|---|
| S1 | タスク一覧 | `/today` `/upcoming` `/no-due` `/done` | メイン画面。ビューはサイドバーで切り替え |
| S2 | タスク詳細パネル | 一覧URL + `?task={id}` | S1の右側に開くパネル。閲覧・編集・サブタスク操作 |
| S3 | 繰り返しルール一覧 | `/rules` | ルールの一覧と有効/停止の切り替え |
| S4 | 繰り返しルール編集パネル | `/rules?rule={id}`（新規は `?rule=new`） | S3の右側に開くパネル |
| S5 | 設定 | `/settings` | JSONのエクスポート/インポート |
| S6 | 計画の取り込み | `/plan` | チャットAIで作業分割した結果（JSON）を確認して登録する（8.2） |
| D1〜D4 | 確認ダイアログ | — | 「6. ダイアログ」参照 |

- ルート `/` は `/today` にリダイレクトする
- 詳細はページ遷移ではなく、URLクエリで開くパネルにする。一覧の文脈を保ったまま編集でき、ブラウザの戻る操作でパネルを閉じられる
- フロントのルーティングに React Router を追加する（requirements の技術構成に追記する）

## 2. 共通レイアウト

```
+------------------+---------------------------------------+------------------------+
| mytask-manager   |  (メインエリア)                         | (詳細パネル: 開いた時のみ) |
|                  |                                       |                        |
| ▶ 今日       (5) |                                       |                        |
|   今後      (12) |                                       |                        |
|   期限なし   (3) |                                       |                        |
|   完了済み       |                                       |                        |
| ──────────────── |                                       |                        |
|   繰り返しルール  |                                       |                        |
|   設定           |                                       |                        |
+------------------+---------------------------------------+------------------------+
   幅 220px 固定          可変                                 幅 420px 固定
```

- サイドバーの件数は未完了の親タスク数（今日ビューは期限切れを含む）。完了済みには件数を出さない
- 期限切れが1件以上あるときは「今日」の件数を赤で表示する
- 画面幅は 1280px 以上を想定する（PC専用）

## 3. S1 タスク一覧

### 3.1 今日ビュー

```
今日  10/14(水)
+--------------------------------------------------------------+
| ＋ タスクを追加（Enterで登録・期限は今日）                       |
+--------------------------------------------------------------+

期限切れ (2)
 [ ] ● 請求書を送る                       10/12(月)        ↻
 [ ] ● 設計レビューの指摘対応      1/3   10/13(火) 18:00
     ├ [x]   指摘1                                         
     ├ [ ]   指摘2                       10/13(火)
     └ [ ]   指摘3

今日 (3)
 [ ] ● 歯医者の予約電話                   10:00
 [ ] ◐ API設計書を書く        進行中                        
 [ ] ○ 週次の振り返り                                      ↻
```

**行の構成**（左から順に）

| 要素 | 内容 |
|---|---|
| チェックボックス | クリックで完了 ⇔ 未着手を切り替える |
| 優先度マーク | ● 高（赤）、◐ 中（黄）、○ 低（グレー） |
| タイトル | クリックで詳細パネル（S2）を開く |
| ステータス | 「進行中」のときだけバッジを表示する |
| サブタスク進捗 | 「1/3」。サブタスクがある親だけ |
| 期限 | 今日ビューでは今日の日付を省略し、時刻だけを出す。期限切れは赤文字 |
| ↻ | 繰り返しから生成されたタスク |

**グループ分け**

- 期限切れ → 今日 の順に並べる。期限切れが0件ならその見出しを出さない
- 各グループの中は、要件 F2 の並び順に従う

**サブタスクの表示**

- 親の下にインデントして表示する。親の左端の ▸/▾ で開閉でき、初期状態は開いた状態
- 条件を満たすのがサブタスクだけの場合は、親を薄い文字（コンテキスト表示）で出し、その下に該当サブタスクを表示する
- 上の例：「設計レビューの指摘対応」は親自身が期限切れなので通常表示

**完了操作**

- 完了にした行は、下部のトースト「完了にしました ［元に戻す］」（5秒）を出してから一覧から消える
- 誤操作の取り消しを手軽にするため

### 3.2 今後ビュー

```
今後
＋ タスクを追加（期限は明日）

明日 10/15(木)
 [ ] ● 定例資料の準備                      14:00
10/19(月)
 [ ] ○ ゴミ出し                                     ↻
11/02(月)
 ...
```

- 期限日ごとに見出しを付けてグループ化する。見出しは「明日」と「M/D(曜)」
- 7日以内は見出しを強調し、それより先は通常の見出しにする

### 3.3 期限なしビュー

- グループ分けはしない。並び順は優先度 → 作成日時
- クイック追加で登録したタスクは期限なしになる

### 3.4 完了済みビュー

```
完了済み
10/14(水)
 [x] ○ 週次の振り返り                    完了 09:12
10/13(火)
 [x] ● 見積もり提出                      完了 17:40
     └ [x] 単価確認
                         [ さらに表示 ]
```

- 完了日ごとにグループ化し、完了日時の新しい順に並べる
- 最初は直近100件だけを表示し、「さらに表示」で100件ずつ追加する
- チェックを外すと未着手に戻り、元のビューに戻る
- クイック追加欄は出さない

### 3.5 状態ごとの表示

| 状態 | 表示 |
|---|---|
| 読み込み中 | 一覧部分にスケルトン（3行） |
| エラー | 「読み込みに失敗しました ［再試行］」 |
| 0件（今日） | 「今日やることはありません」 |
| 0件（その他） | 「タスクはありません」 |

### 3.6 クイック追加

- タイトルを入力して Enter で登録する。それ以外の項目は既定値（優先度は中、ステータスは未着手）
- 期限の既定値は、今日ビューなら今日、今後ビューなら明日、期限なしビューならなし
- 登録後も入力欄にフォーカスを残し、続けて入力できるようにする
- 細かい設定は、登録後に詳細パネルで行う

## 4. S2 タスク詳細パネル

```
+------------------------------------------+
| ×                              [削除]     |
| [ ] タイトル________________________      |
|                                          |
| ステータス  [未着手 ▼]                     |
| 優先度      ( )高 (●)中 ( )低              |
| 期限        [2026/10/14] [10:00] [クリア]  |
| 繰り返し    毎週月曜  → ルールを開く         |
|                                          |
| メモ                                     |
| +--------------------------------------+ |
| |                                      | |
| +--------------------------------------+ |
|                                          |
| サブタスク  1/3                           |
|  [x] 指摘1                 ●  10/13      |
|  [ ] 指摘2                 ◐             |
|  [ ] 指摘3                 ○             |
|  ＋ サブタスクを追加                        |
|                                          |
|               [キャンセル] [保存]          |
| 作成 10/10 09:00 ・ 更新 10/13 18:02      |
+------------------------------------------+
```

**編集と保存**

- 編集方式は「明示的に保存」。React Hook Form と Zod で入力をチェックする
- 未保存の変更がある状態で閉じようとしたら、D4（破棄の確認）を出す
- チェックボックスの切り替え、サブタスクの追加・チェック・削除は、ボタンを押さずにその場で即時保存する（一覧と同じ操作感にするため）

**期限**

- 日付と時刻を別々の入力欄にする
- 時刻は日付が入っているときだけ入力できる。「クリア」で日付と時刻を両方消す

**サブタスク**

- サブタスクの行をクリックすると、パネルの中身がそのサブタスクに切り替わる
- 上部に「← 親タスク名」のリンクを出して、親に戻れるようにする
- サブタスクのパネルには「サブタスク」セクションを出さない（1階層の制約）

**その他**

- 繰り返しの行は、ルールから生成されたタスクにだけ表示する
- 入力チェック：タイトルは必須で1〜200文字。時刻だけを入れることはできない
- 削除ボタンを押すと、D2（サブタスクがある親の場合）または簡易確認を出してから削除する

## 5. S3 繰り返しルール一覧 / S4 編集パネル

### 5.1 S3 一覧

```
繰り返しルール                                    [＋ 新規ルール]

 有効  タイトル          パターン              次回        
 [on]  週次の振り返り    毎週 月              10/19(月)
 [on]  ゴミ出し          毎週 月・木           10/15(木)
 [off] 家賃振込          毎月 末日             —（停止中）
```

- 行をクリックすると S4 を開く
- 有効のトグルは即時保存する。停止すると次回の欄は「—」になる
- 次回の生成日は、ルールから計算してサーバーが返す

### 5.2 S4 編集パネル

```
+------------------------------------------+
| ×                         [ルールを削除]   |
| タイトル  [週次の振り返り___________]       |
| 優先度    ( )高 (●)中 ( )低                |
| 期限時刻  [__:__]（任意）                   |
| メモ      [____________________]          |
|                                          |
| パターン  (●)毎週 ( )毎日 ( )毎月           |
|   曜日    [月][火][水][木][金][土][日]       |
|   (毎月の場合) 日付 [ 15 ▼]  ※ 「末日」も選べる |
| 開始日    [2026/10/14]                     |
| 終了日    [__________]（任意）              |
|                                          |
| サブタスクのひな形                          |
|   ・アウトプット確認        ◐  [×]         |
|   ・来週の計画              ◐  [×]         |
|   ＋ 追加                                  |
|                                          |
| 次回の生成予定: 10/19(月), 10/26(月), 11/2(月)|
|                                          |
|               [キャンセル] [保存]          |
+------------------------------------------+
```

- パターンの選択によって、曜日の入力欄と日付の入力欄を切り替える
- 毎週の場合は、曜日を1つ以上選ぶことを必須にする
- 「次回の生成予定」には直近3回分を表示する。設定ミスに保存前に気づけるようにするため（サーバーのプレビューAPIで計算する）
- 保存時に「変更は次回生成分から反映されます」とトーストで知らせる

## 6. ダイアログ

| ID | 表示するタイミング | 文言（例） | ボタン |
|---|---|---|---|
| D1 | 未完了のサブタスクが残る親を完了にするとき | 「未完了のサブタスクが2件あります。すべて完了にしますか？」 | キャンセル / すべて完了 |
| D2 | サブタスクがある親を削除するとき | 「サブタスク3件も削除されます。削除しますか？」 | キャンセル / 削除（赤） |
| D3 | インポートを実行するとき | 「現在のデータはすべて置き換えられます。（タスク120件 → 85件）」 | キャンセル / 置き換える（赤） |
| D4 | 未保存の変更があるパネルを閉じるとき | 「変更を破棄しますか？」 | 編集に戻る / 破棄 |

- ルールを削除するときは、「生成済みのタスクは残ります」と書き添えた簡易確認を出す

## 7. S5 設定

```
設定

バックアップ
  [JSONをエクスポート]   最終エクスポート: 10/10 21:00
  [JSONをインポート...]  ファイルを選ぶ → 件数プレビュー → D3
```

- エクスポートは `mytask-manager-YYYYMMDD-HHmm.json` という名前でダウンロードする
- 最終エクスポート日時はブラウザ（localStorage）に保存する。バックアップ忘れに気づくための目安で、正確でなくてもよい
- インポートは、ファイルの形式チェックに失敗したらエラーを表示して中止する

## 8. Phase 6 で追加した画面要素

| 場所 | 追加したもの |
|---|---|
| サイドバー | 上部に検索欄（Enter で `/search?q=…`）。下部にショートカットの案内。スクロールしても固定 |
| 検索画面 `/search` | 「検索 「語」」の見出し、件数、結果の一覧（S1 と同じ行）。行をクリックすると S2 を開く |
| S1 の行 | 期限が今日以前の未完了タスクに、マウスを乗せると「明日へ」ボタン |
| S2 の期限欄 | 「今日」「明日」「来週月曜」ボタン |
| S5 | 「自動バックアップ」カード（保存先・パスをコピー・直近5件のファイル） |
| ブラウザのタブ | 今日の件数（例：`(3) mytask-manager`） |
| サイドバー・ページ見出し | 英語＋日本語の2段：Today 今日 ／ Upcoming これから ／ Someday いつか ／ Done 完了 ／ Routines 繰り返し ／ Settings 設定 ／ Search 検索 |
| ロゴ | Orbit：「今日」を表す惑星（チェック入り）と、その周りを回る軌道・衛星。クリックで Today へ。favicon も同じマーク |
| S1 の行（Phase 8 で見直し） | 優先度は「高」だけ赤い印（中・低は出さない。印の場所は常に確保してタイトルをそろえる）。「進行中」と「✓ 1/3」はタイトルのすぐ後ろ。右端は期限（固定幅・右寄せ）と ↻ だけ。サブタスクは親のタイトル位置まで字下げし、└ 型のガイド線で親とつなぐ |
| S5（Phase 12 で見直し） | 先頭に「保存場所」カード：① データ本体 ② 自動バックアップ ③ コピー先 ④ ログ ⑤ 手動バックアップ を、役割と「触ってよいか」の説明・パスをコピー付きで一覧にする。パスはここだけに出し、自動バックアップ・このアプリについてのカードからは外す。コピー先には「✓ コピー済み N件（最新 …）」を出す。旧名（mytask-manager-auto-*）のファイルには「名前変更前」の注記 |

### 8.1 Phase 13 で追加したエリア

| 場所 | 追加したもの |
|---|---|
| サイドバー | ロゴの下にエリアのタブ（「すべて」＋各エリア。色の点つき）。2列の格子に同じ幅で並べ（Phase 14 で見直し。折り返しで最後の1つだけが行全体に広がらないように）、長い名前は省略してツールチップで全体を出す。エリアがなければ出さない |
| ページ見出し | エリアを選んでいるとき、見出しの横にエリア名のバッジ（設定画面を除く） |
| S1 の行・S3 の行 | 「すべて」のときだけ、親の行の頭にエリアの色付きバッジ（サブタスクには付けない） |
| クイック追加 | 選んでいるエリアに入る。`@名前` で指定するとプレビューに「エリア ○○」 |
| S2・S4 | 「エリア」の選択（各エリア＋未分類）。サブタスクの詳細には出さない |
| S5 | 先頭に「エリア」カード：名前・色・タスク数とルール数・↑↓・削除、追加欄（まだ使っていない色を選んでおく）。10個に達したら追加欄の代わりに上限の案内 |
| D5 エリアの削除 | タスクかルールがあれば件数と「移動先」（ほかのエリア／未分類）を選ばせる |

### 8.2 Phase 14 で追加した計画の取り込み（S6）

サイドバーの Routines と Settings の間に「Plan 計画の取り込み」。上から3枚のカードで、1→2→3 の順に進める。

| カード | 内容 |
|---|---|
| 1. プロンプトをAIに渡す | 「プロンプトをコピー」ボタン。プロンプトには今あるエリア名と今日の日付を埋め込む。「プロンプトを見る」で全文を開ける（コピーできない環境向け） |
| 2. AIが出したJSONを貼り付ける | テキスト欄と「内容を確認」。最初の `{` から最後の `}` までを JSON として読むので、コードブロックや前後の説明文ごと貼ってよい。形の誤りと、サーバーが返した項目ごとの誤り（`tasks[0].dueDate：…`）を一覧で出す。テキストを書き換えたら 3 を消す |
| 3. 確認して登録する | 確認（dryRun）が通ったときだけ出す。「登録先のエリア」（JSON の area を大文字小文字を問わず当てはめる。無い名前なら選んでいるエリアにして知らせる）、親タスクごとに「登録／飛ばす」・タイトル・期限・優先度（高のみ）・サブタスク（開くと一覧）。「N件を登録」で登録し、トーストを出して 2 を空に戻す |

### 8.3 Phase 15 で追加した目安時間

| 場所 | 内容 |
|---|---|
| S2 詳細パネル | 期限の下に「目安時間」。「90」「1h30m」などで入力し、欄を離れると「1h30m」の形に整える。読めない入力は欄の下にエラーを出し、保存しない。サブタスクに目安があれば、右に「サブタスク合計 10h30m」を出し、親の目安を超えていれば「（2h30m 超過）」を付けて黄土色の太字にする。サブタスクの一覧の各行にも目安を出す |
| S4 ルール編集 | 期限時刻の上に「目安時間」。ひな形の各行に、タイトルと優先度の間の小さな「目安」欄 |
| S6 計画の取り込み | 親の行に「目安 8h」、サブタスクの見出しに「合計 10h30m」、各サブタスクに目安。合計が親を超えていれば注意の1行を出す |

- 一覧の行には目安を出さない（行を混ませないため。必要になったら追加を検討する）

### 8.4 Phase 16 で追加した今日の目安と計画の進み具合（Progress）

- Today の見出しの進み具合を「1件完了・残り2件・目安 3h30m」にする。目安は今日ビューに残っている作業の合計で、目安が1つもなければ出さない
- サイドバーの Routines と Plan の間に「Progress 計画の進み具合」。計画ごとに1枚のカードで、上から次を並べる

| 部分 | 内容 |
|---|---|
| 見出し | 計画名と状態のバッジ（順調＝青、遅れ＝赤で「（期限切れ N）」付き、完了＝灰）。「すべて」のときはエリアのバッジも出す |
| バー | 完了したステップの割合と「1/10 ステップ」 |
| 数字 | 残りの目安（／全体）、最終期限（あとN日）、必要なペース（週 5h40m）。値がないものは出さない |
| 次 | 次にやるステップ（押すと詳細パネル）と期限。期限切れなら赤 |
| ステップの一覧 | 折りたたみ。状態の印（✓・◐・○）、タイトル（押すと詳細パネル）、サブタスクの進み具合、目安（途中なら「残り 1h30m / 2h30m」）、期限 |

- 計画がなければ、どういう形のタスクがまとまるかを案内する

## 9. 決定事項

- 詳細パネルは「保存」ボタンで保存する方式（自動保存にはしない）
- 完了にした行は、トーストを出した後に一覧から消す
- サブタスクだけがビューの条件を満たす場合は、親を薄い文字で表示する
